# 从赛题到完整论文的证据化工作流

本流程解决一个常见失败模式：代码已经算出结果，但模型推导没有完整进入论文；优化只跑一次，没有收敛、稳定性和独立验证；题意存在多种目标口径，却在写完后才作为“局限”提及。

## 0. 资料隔离——先分清是演练还是实战

两种模式的隔离尺度不同，**别把演练的自我约束带进实战**。

| | 盲测演练 | 正式比赛 |
|---|---|---|
| `corpus/`、`建模/` 里的同题论文、题解、结果 | 禁止 | 本来就没有（当年新题） |
| 通用写作规范、方法脚手架 | 允许 | 允许 |
| **公开文献、国家标准、行业既有方法** | **禁止**（否则演练失真） | **必须查，这是加分项** |

- 两种模式下工作目录的 `inputs.mode` 都设为 `official-only`，指的是**数据**只用官方题目与附件。
- 盲测演练额外禁读同题论文；语料库只用于方案冻结后的复盘，复盘结论不得反向伪装成盲测时独立得到的结论。
- **实战必须有「行业标准/既有方法检索」这一步**，检索到的标准、公式、参数写进参考文献。
  2025 B 题的官方优秀论文 B157 引了 GB/T 42905-2023《碳化硅外延层厚度的测试 红外反射法》，
  直接对上工业界的既有做法；同题的盲测演练因规则放弃了这条路——**盲测该放弃，实战放弃就是白扔分**。

## 1. 先建立模型卡

每个子问题先填写 `case.json`，再写求解代码。模型卡至少回答：

1. 题目要求的待求量是什么，单位和统计口径是什么；
2. 属于直接计算、机理、仿真、优化、预测还是评价；
3. 决策变量、状态量、参数和约束分别是什么；
4. 目标函数或评价指标如何数学化；
5. 存在哪些题意歧义，有哪些候选口径；
6. 采用哪个口径，依据是题目文字、物理含义还是任务场景；
7. 哪些假设是题目给定，哪些是团队新增，新增假设会影响什么。

若存在多个合理指标，不要凭直觉直接选一个。先分别定义并在简化场景上比较；正式模型采用一个主指标，其他指标作为口径敏感性结果报告。

## 2. 建立可追踪的数学模型

- 先写统一的时间、空间、索引和单位约定，再分别推导状态方程、观测/判定方程、目标与约束。
- `equation_code_map` 为每组核心方程登记实现函数和测试文件。论文公式、代码和测试必须表达同一个模型。
- 对几何、动力学或集合判定，至少构造一个可手算特例；对离散模型，保存网格/步长收敛实验。
- 所有进入论文的数值先写入 `artifacts/results.json`，论文生成器只读该文件，禁止手工转抄。

## 3. 基线、主方法与分解审计

- 先建立简单、透明、可快速复算的基线，再使用主算法。基线用于发现目标方向、单位、约束或索引错误，不要求性能最好。
- 耦合决策变量默认联合优化。逐变量、逐资源或逐时间贪心只能作为计算加速方法，不能默认等价于联合最优。
- 若使用分层、任务分配、贪心追加或滚动优化，在缩小规模上运行联合搜索或精确方法，记录目标差距；没有对照时只能称“启发式可行解”。
- 能写成线性、整数或凸规划时优先使用可给出最优性证据的方法；不可导、多峰问题才使用差分进化、遗传、退火等启发式算法。

## 4. 保存实验记录

迭代或随机算法必须保存：

- 算法名称、实现入口、参数、随机种子、迭代上限和终止原因；
- 每代/每轮最佳目标值，用于收敛曲线；
- 至少 3 个固定种子的完整运行结果，以及最好、最差、均值和标准差；
- 最终解的逐约束残差、最大违反量和总体可行性；
- 运行耗时和硬件信息仅在计算量构成论证的一部分时记录。

不要只保留“最好的一次”，也不要从日志截图中人工读取数值。使用 `snippets/model_validation/` 生成可序列化的统计与约束报告。

## 5. 按任务类型验证

| 类型 | 最低验证组合 |
|---|---|
| 直接计算 | 手算/解析结果或第二段独立实现 |
| 机理与仿真 | 量纲检查 + 解析特例/独立实现；有离散时再做步长或网格收敛 |
| 优化 | 基线 + 多种子稳定性（随机算法）+ 逐约束审计 + 第二算法/缩小规模精确解/上下界之一 |
| 预测 | 基准模型 + 留出或交叉验证 + 残差分析 |
| 综合评价 | 标准化/赋权敏感性 + 排序稳定性 |

“换一个随机种子继续跑同一段代码”不是独立验证。独立验证应改变算法、实现路径或证据来源。

## 5.5 实验设计：主动去找系统误差

上一节查的是「模型自洽吗」，这一节查的是「模型漏了什么」。两件事，别合并。

**没建进模型的系统效应通常不会让残差变难看**，而是让估计值随所用数据区间平移。只在全量数据上算一次，这种漂移完全看不见。所以下面两条建议当标准动作跑：

- **子区间漂移扫描**（`snippets/model_validation` 的 `subrange_drift_scan`）：把待求量在数据的不同子区间上各算一遍。单调漂移几乎一定是漏建模，来回跳更像噪声。2025 B 题里它测出光程随波段漂移 12%（硅）与 34%（碳化硅），直接解释了三篇同题论文结果分歧的来源。
- **多工况联合拟合**（同目录的 `joint_fit`）：若干量在各组数据之间本来就该相同时，联合拟合共享它们，而不是各组各拟一遍再取平均——后者等于扔掉了这条硬约束，组间散布会反过来变成主要误差来源。2025 B 题演练两个入射角各拟各的，角度间半散布 0.0704 µm 成了主导不确定度；同题官方论文 B157 用双角联合拟合避开了这个问题。

**标定/尺度这类讨厌参数要显式建进模型**，不要预先归一化了事。把仪器增益、基线偏移当成待估参数一起拟合，它们的估计值本身就是数据质量的证据——2025 B 题两个角度拟出的 scale 相差 10.5%，这个数字直接指出精度瓶颈在仪器绝对标定而不在算法。

不确定度要分解到来源（形式协方差、波段/子集选择、工况间散布……），报告里说清**哪一项是主导的**。只给一个 ± 数字而不说它从哪来，评委无法判断该不该信。

## 6. 每问的论文内容契约

每个子问题的正式章节必须形成以下闭环：

1. **问题分析**：为什么选该模型，难点和与前问的关系；
2. **模型建立**：变量、参数、目标、约束、假设和完整推导；
3. **算法设计**：输入输出、步骤、停止条件、复杂度或降维依据；
4. **求解结果**：核心参数、方案、目标值和可行性；
5. **模型验证**：收敛、稳定性、独立算法或敏感性证据；
6. **结果解释**：结果为何合理、相对基线改善多少、适用边界是什么。

每一项该展开到什么程度——一个公式配哪几句、一张图怎么导入和解读、算法小节必须含哪四样——见 `analysis/exposition-guide.md`，那里按元素给了模式和官方论文原文对照。`templates/paper_skeleton.py` 能把这些元素直接生成为论文里的 TODO 槽位，漏写时看得见。

这六项是**内容要求，不是节标题**。`templates/paper.tex` 和 `templates/paper_template.docx`
按国赛惯用版式排四个小节，对应关系如下——照模板写不会漏内容，不要另开两节：

| 契约内容 | 模板中的位置 |
|---|---|
| 1 问题分析 | 顶层 `\section{问题分析}`（在「模型的建立与求解」之前，统一交代各问思路） |
| 2 模型建立 | `\subsubsection{模型建立}` |
| 3 算法设计 | `\subsubsection{算法设计与求解}` |
| 4 求解结果 + 6 结果解释 | `\subsubsection{结果分析}`（先报方案和目标值，再解释为何合理、相对基线改善多少、边界在哪） |
| 5 模型验证 | `\subsubsection{模型验证}` |

不设置页数、公式数或图片数**硬门槛**——完整性以模型卡和证据链为准，图表用于表达流程、收敛、敏感性、空间/时间结构和方案对比，不为凑数量添加装饰图。

但「不设硬门槛」不等于「不用管体量」。`analysis/paper-structure.md` 用官方优秀论文实测出了一个分布，交稿前应当拿自己的论文去比一比，`checklist/case_audit.py` 的完备性对标分节会自动给出这张表。两条最容易踩空的：

- **附录要带全量代码**。官方 2023 年 14 篇实测附录占全文 27.6%~72.1%（中位 49.9%），正文里只写「程序见支撑材料」等于白丢一半篇幅。代码本来就写好了，用 `templates/appendix_code.py` 一行灌进去即可。2025 B 题演练漏了这一步，附录占比 4.3%，光这一项就差了 25 页。
- **图要够，且图应多于表**。官方样本图中位 20.5 张、11/14 篇图多于表。每问配「现象/数据概览、模型示意、拟合叠合+残差、收敛轨迹、敏感性扫描、结果对比（带误差棒）」这一组，3 问就是 15~18 张，自然落进区间；具体见 `analysis/figure-guide.md`。

体量偏低本身不是错，但它几乎总是在提示某个证据没画出来、某段推导没写完整。

## 7. 运行审计

初始化比赛目录：

```bash
python templates/init_contest_case.py work/2026-A --case-id 2026-A --questions 5
```

生成论文前和提交前各运行一次：

```bash
python checklist/case_audit.py work/2026-A
python checklist/compliance_check.py work/2026-A/paper/paper.tex
```

`case_audit.py` 默认只告警、不阻断。若仍有告警，可以生成带缺口说明的草稿，但不得在交付时称为完成版；最终答复必须列出未解决警告。团队主动启用质量门槛时使用 `--strict`。

**这个审计只做结构检查**：字段填没填、登记的文件在不在。它不打开证据文件、不判断结论是否成立——`ambiguities_reviewed` 写 `true` 就算审过，`validations` 登记一条独立验证只要文件存在（哪怕内容是 `{}`）就算数。所以「0 个警告」只说明证据可定位，不是质量背书；内容真伪一律走 `checklist/manual_verification.md`。

`case.json` 里的尖括号 `<...>` 是填写口径提示，审计器一律判为未填写，不会被当成已完成。某一问的 `task_type` 还是 `unclassified` 时，该问后续检查全部跳过（未分类就没有验证判据），报告末尾会写明跳过了几问——警告数少不等于快做完了。

报告末尾另有三个分节，**都不计入警告数、不影响 `--strict` 退出码**：

- **完备性对标**：把论文体量与官方优秀论文的实测分布逐项对照（基准与口径见 `checklist/paper_completeness.py`，可单独运行）。分开是因为篇幅达标和研究质量是两件事，混在一起会让人以为凑几张图就能提质量。2025 B 题演练那篇 16 页论文当时报的是「0 个警告」，缺的正是这一眼。
- **证据利用率**：反过来查 `artifacts/` 里算出来的东西有几份真在论文里有图或表。按露面方式分四档——登记为 `evidence_displays`、有对应插图、仅正文引了个路径、完全没露面。同一次演练实测 10 份证据只有 3 份有图表、1 份只被引了路径、5 份登记了却没展示、1 份压根没登记。**图不够的时候先来这里找**：这些是已经花掉机器时间算完、只差一张图的东西，比凭空想选题强。
- **小节展开度**：把各问同名小节的汉字数并排列出来，报最短、最长和倍数，并统计骨架里还没填掉的 `% TODO(小节/元素)` 槽位数。这一节**不用外部基线**——小节级的语料基线做不出来（从 `corpus/official-2023` 的 14 篇提取件自动切章，与本仓库已实测的占比交叉验证只有 2/14 吻合，pdftotext 把公式打散成了像标题的短行），编一个阈值比不给更糟。同名小节在各问之间差几倍是硬事实，拿论文自己作参照就够刺眼了。**最短的那节往往不是漏写，而是内容放错了小节**：2025 B 题演练「算法设计与求解」三问 59/346/117 字，翻开 59 字那节，里面写的是群光程与相光程的推导，本该在「模型建立」；而契约要求的输入输出、步骤、停止条件、复杂度四样一样都没有。该怎么展开见 `analysis/exposition-guide.md`，`templates/paper_skeleton.py` 能把这些元素直接生成为 TODO 槽位。

证据没露面本身不算错——诊断类、过程类的图本就该放支撑材料而不是塞进正文。工具只让「算了但忘了用」看得见，不替你决定。

## 示例的正确用途

`examples/示范论文/` 只示范“计算 → results.json → LaTeX”的单一数据源组织方式，不是目标篇幅或研究深度范本。正式比赛应按本流程补齐每问的模型与验证证据。
