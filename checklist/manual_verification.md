# 人工核对清单（提交前强制步骤）

对应设计文档"⑥ AI 建模方案与正文写作"的护栏：AI 起草的所有定量结论，定稿前必须逐条过这份清单，负责整合的人签字确认（哪怕只是在这份文件里打勾）后才能提交。

## 定量结论核对

- [ ] 正文里出现的每一个数值结果，是不是真的跑代码算出来的（不是 AI 凭经验编的"合理数字"）？
- [ ] 每一条公式推导，团队里至少一人独立手推/口头过一遍，确认没有跳步或错误？
- [ ] 图表里的数据和代码实际输出是否一致（没有为了"好看"手动改数）？
- [ ] AI 起草的模型假设，是否和实际用到的求解方法真的匹配（不是套话）？

## 建模方案核对（对应组件⑥"多方案生成"）

- [ ] AI 提出的候选方案里，团队是否真的理解了每个方案的原理，而不是选了个名字听起来对的？
- [ ] 选定方案后，是否核实了它对当前题目的数据/约束是适用的（不是从别的题目模板照搬）？
- [ ] 每个子问题是否在 `case.json` 中明确了待求量、单位、决策变量、目标函数、约束和新增假设？
- [ ] 是否逐项审查了题意歧义，并记录候选指标、最终口径和选择依据，而不是把歧义推迟到“模型局限”？
- [ ] 盲测阶段是否只使用官方题目和附件，没有读取 `corpus/`、`建模/` 中的同题论文、结果或代码？

## 代码、优化与实验核对

- [ ] 每组核心方程是否在 `equation_code_map` 中关联到实现函数和测试，且测试验证的是同一数学定义？
- [ ] 是否先建立了透明基线，再使用主模型；正文是否给出相对基线的改善而非只报最终值？
- [ ] 随机算法是否至少运行 3 个固定种子，并保存最好、最差、均值、标准差和原始运行记录？
- [ ] 迭代算法是否保存了收敛轨迹、终止条件和终止原因，而不是只画一张无法复算的截图？
- [ ] 每个优化结果是否生成逐约束残差报告，最大违反量在允许误差内？
- [ ] 使用贪心、分层或分解算法时，是否在缩小规模上与联合优化/精确解比较并报告差距？
- [ ] 每问是否至少有一种与主求解路径相对独立的验证，而不是只换随机种子重复同一段代码？

## 论文证据链核对

- [ ] 每个子问题是否形成“分析 → 模型 → 算法 → 结果 → 验证 → 解释”的完整闭环？
- [ ] 论文里的数字是否由生成脚本从统一 `artifacts/results.json` 插入，代码、JSON、图表和正文是否一致？
- [ ] `python checklist/case_audit.py <比赛目录>` 是否已运行；若仍有警告，交付说明是否逐条披露并明确当前稿为草稿？
- [ ] 是否避免把 `examples/示范论文/` 的 10 页当成目标篇幅，而按实际问题复杂度完整展开模型与证据？

## 格式与合规核对（配合 `checklist/compliance_check.py`）

- [ ] 跑过 `python checklist/compliance_check.py <论文.tex>`，摘要、图表 caption、明确身份字段和 AI 声明均通过自动初筛，输出"未发现问题"？
- [ ] 导出最终 PDF 后，是否人工复查了文件名、文档属性、图片和附件中的学校/队员/参赛编号？这些内容不能仅靠 `.tex` 文本检查。
- [ ] AI 工具的用途、正文对应标注与参考文献条目是否与实际使用一致？自动检查只能确认声明形式存在。
- [ ] 参考文献是否按 `analysis/writing-style-guide.md` 的 GB/T 7714 格式？
- [ ] 是否过了一遍 `analysis/judge-deductions.md` 的每一条？

## 使用方式

赛时负责整合的人在提交前，把这份文件复制一份到当次比赛的工作目录，逐条打勾。`case_audit.py` 默认只告警，不代替人工判断；未解决项必须在交付说明中披露，不能把草稿描述为完成版。
