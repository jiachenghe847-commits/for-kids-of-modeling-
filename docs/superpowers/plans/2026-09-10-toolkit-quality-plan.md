# 数模工具箱独立成稿质量提升方案

> 面向实施者：按任务顺序执行，可使用 superpowers:executing-plans 分阶段检查。本文只制定方案，没有实施工具箱功能修改。

**Goal:** 给定一道完整往年国赛题及官方附件，在隔离同题资料的全新会话中，使用冻结后的通用工具箱完成求解与论文，正文体量、章节展开和图像呈现接近匹配的官方优秀论文，并通过计算与证据核验。

**Architecture:** 保留现有模型卡、计算脚手架和 LaTeX 数据链路，增加干净的盲测发行包、统一质量基准、实验到论文的证据映射、最终 PDF 检查以及可执行的交付验收。求解者只接触通用规则与官方输入；同题范文由验收方在产物冻结后用于评审。

**Tech Stack:** 现有 Python、pytest、NumPy/SciPy、Matplotlib、XeLaTeX；PDF 信息、文本与页面渲染优先复用本机 Poppler 工具。

**Spec:** 本文“目标与边界”“验收契约”即本方案的需求依据；数值容差是建议的项目标准，不是官方评分标准。

## 目标与边界

- 本期优先覆盖本科组常见机理/仿真、优化和数据分析类任务。补齐通用研究与成稿链路，算法扩充由实际验收暴露的缺口驱动。
- 默认采用严格盲测：官方题目、完整附件、空白提交表格、冻结的通用工具箱；不读取语料库、已有演练解答、复盘、同题网络资料或外部文献。用户若选择模拟实战模式，另设允许通用文献的测试配置，不混报两种成绩。
- 工具箱完善阶段可使用已有通用分析和开发样例。需要重新测量范文时，属于开发/评审工作；原文、同题结论和参数不得进入求解发行包。
- 现有 2025 A/B 演练已经暴露解答和复盘，只做开发回归，不再充当未见题验收。
- 首次交付验收使用用户在版本冻结后提供的一道未用于开发的完整题。通过一道题只证明该题表现；跨题型稳定性需追加不同题型的留出测试。
- 研究质量包含题意正确、计算可信、结果可复核、局限诚实，不承诺任意赛题都能自动达到获奖水平或保证获奖。
- 本方案不提交 Git、不更改旧演练结果、不读取凭据文件。

## 已确认的现状（2026-09-10）

只读运行全仓基础测试：162 passed，1 条 statsmodels/NumPy 弃用警告；不含重新执行整题求解。

现有 B 题 PDF 为 16 页。运行 `case_audit.py ... --strict` 返回 0，报告显示 0 个警告、6 张图、8 张表，10 份证据中 3 份有图表展示；算法小节汉字数分别为 59/346/117。这些是检查器输出，不等于已人工确认每份证据内容。

发现六项阻碍：

1. 审计主要检查登记和路径存在，无法拒绝空证据、错误证据或过期结果。
2. 完备性对标、小节展开和证据展示不影响严格模式；旧测试刻意保证这一语义。
3. 基准采用 PDF 提取的 CJK+字母数字，当前成稿字数主要数 TeX 汉字；附录长度又包含 TeX 命令，不能直接作同口径比较。
4. `paper_completeness.py` 把跨年代正文均值 12000–13000 当成单篇区间，缺少支持这一单篇阈值的分布。
5. 已有配图风格与常用图函数，但缺少最终插入尺寸、页面可读性和完整 PDF 的交付检查。
6. 通用文档及初始化示例包含具体赛题的结论、数值与做法，仅排除 `corpus/`、`建模/` 不足以保证盲测隔离。

## 验收契约

### 基准怎么建立

- 从不同年份、相近题型的官方优秀论文建立开发基准；默认每类至少 5 篇，不足时标记样本不足，不凭空生成四分位区间。
- 用同一套 PDF 测量流程统计参考论文和候选论文：摘要、正文起止、正文页数、正文 CJK+字母数字字符数、图表数量、主要章节比例、附录页数、总页数。记录部分页面的章节边界；无法可靠识别时要求人工标注。
- 图数按实际编号的图对象统计；一个编号下多个子图不拆成多张，同时保留子图信息供视觉评审。以最终 PDF 为准，源文件只辅助追踪。
- 扫描版需要 OCR 与人工核对，无法可靠提取字符数的样本只参与页数和视觉对比，不混入文本分布。
- 同题范文优先用于最后评审。比较集与统计方法在运行前固定；数量不足 3 篇时用冻结的同类基准进行量化判定，同题样本作定性对照。
- 求解包只携带跨题型汇总的体量区间、原创通用范例和质量规则，不携带目标题参考值、方法或图。

### 建议采用的通过标准

| 维度 | 标准 | 判定方式 |
|---|---|---|
| 资料隔离 | 只使用允许材料；工具箱与输入版本固定 | 发行包清单、文件哈希、受限访问环境与过程记录；不能只凭自述 |
| 完整解题 | 全部小问和官方提交表均完成，核心计算可重跑，无已知重大题意或计算错误 | 逐问输出核对、独立验证与结果复算 |
| 章节内容 | 每问具备分析、模型、算法、结果、验证、解释；允许合理共享内容并准确引用 | 自动定位加语义复核；标题存在不能单独通过 |
| 正文体量 | 正文页数及同口径字符数默认均在匹配范文中位数的 80%–125% | 项目建议容差；冻结后不得为适配某次输出而放宽 |
| 总页数与附录 | 分开列出总页数、正文、参考文献和附录；总页数超出匹配中位数 70%–130% 时必须复核 | 总页数偏差主要来自完整代码长度时可说明通过；正文不足不能用附录抵消 |
| 图表覆盖 | 正文关键主张全部有恰当的图、表或推导支撑；同类图数 Q1–Q3 作参考 | 图少须查遗漏证据，图多须查重复；不强制每问相同图数或图多于表 |
| 图像技术质量 | 数据图可重跑；优先矢量；位图按最终插入尺寸有效分辨率至少 300 dpi；图中文字目标不小于 8 pt | 导出元数据、PDF 对象/尺寸检测及实际页面目检；无法自动测量不记为通过 |
| 视觉质量 | 无缺字、裁切、严重遮挡、错误图例/单位；图文对应，排版与范文相近 | 最终 PDF 每页检查，全部正文图逐张检查，保留页码证据 |
| 可复现性 | 关键数值、图表数据、官方表格与论文一致，能够从官方输入重建 | 数值按预先登记容差比较；时间戳/PDF 元数据等不要求逐字节一致 |

正文体量超出建议区间时进入“需复核”，不能自动宣布通过，也不直接要求扩写或删减。评审方必须指出偏差来源，检查内容覆盖和重复情况后才能批准例外；作者自己写一句理由不能解除门槛。

语义与视觉采用五项 1–5 分量表：模型推导、算法说明、结果解释与验证、图表表达、篇章组织。1 分代表缺失/严重错误，2 分代表多处实质缺陷，3 分代表基本可用但明显薄弱，4 分代表完整清楚且只有局部小问题，5 分代表精确充分、易于核验。参考与候选统一量表、尽可能隐去来源信息。建议候选每项至少 4 分，平均分距参考平均分不超过 0.5；评分必须附具体章节/页码依据。不同评审分差超过 1 分时复核，不把大模型自评分当作独立证明。

只有隔离、研究证据、论文呈现及复现四方面均通过才报“通过”。任一未评审项显示“未评审/需复核”，不得以 0 警告替代。

## 实施顺序与交付物

### 任务 1：统一测量与版本化基准

**修改/新增：** 修正 `checklist/paper_completeness.py`，新增 `checklist/pdf_metrics.py` 与 `benchmarks/` 中的测量清单和汇总数据。

- [ ] 先用可人工核对的小型 PDF 样本验证正文/附录边界、子图、多文件 TeX、数字与中文混排的测量口径。
- [ ] 将“原始测量值、抽样来源、题型、测量可靠性、统计口径和版本”分开保存；扫描件缺失指标为未知，不作 0。
- [ ] 参考与产物使用相同指标；删除把均值范围解释成单篇合格区间的行为。
- [ ] 冻结项目验收配置与比较集；旧报告保留为历史基线，不回写过去的结论。

**验收：** 人工标注样本的总页数一致；正文边界可回溯；图号与子图计数规则一致；任何不能可靠计数的指标显式请求复核。

### 任务 2：构建干净的盲测工具箱

- [ ] 用允许清单导出运行所需的代码、空白模板、通用指南；不复制 `.git`、语料、历史演练、复盘、缓存和本开发计划。
- [ ] 将赛题专属例子、数值、范文摘录迁至开发资料；运行指南换成原创通用例子。检查初始化器、代码注释、测试夹具和 README 的内容泄漏。
- [ ] 发行包附文件清单、哈希、版本和可复现依赖信息；在源仓库不可访问的环境中验证运行。单纯复制到同一主机目录不等于隔离。
- [ ] 最终测试启用没有开发历史上下文的新会话，关闭外部检索；官方输入另行注入。操作系统或容器访问限制不能实现时，明确标为软隔离测试，不能算严格盲测通过。

**验收：** 通用例题从发行包独立运行；无法访问原仓库和禁用资料；发现禁用文件/已知专属片段时拒绝导出。片段扫描只是补充，不能宣称它能识别全部语义泄漏。

### 任务 3：将研究流程变成阶段性检查

**修改：** 初始化模型卡、模型工作流、`checklist/case_audit.py`；新增 `checklist/evidence_audit.py`。

- [ ] 扩展模型卡到版本 2，加入逐问交付要求、实验计划、证据登记、论文映射与运行记录；保留版本 1 的旧结构审计。
- [ ] 每问先定义关键结论、对应计算/推导、验证判据和预期展示，再跑实验。按直接计算、机理仿真、优化、预测、评价选必要验证，不要求所有题都做同一种检验。
- [ ] 开始论文前要求核心结果与必要验证齐备；阈值由题意、数值误差或实验设计给出，不能事后为了通过而调整。
- [ ] 打开并校验证据内容，拒绝空 JSON、非有限数值、缺列、错单位、过期哈希、种子不足、失败约束被写成成功等情况。
- [ ] 为核心数学结论安排解析特例、第二实现、合成数据回收或缩小规模精确解。结构检查通过不代表方法在领域上成立，另需语义复核。

**最低接口：** 证据记录包含 id、question_id、kind、path、producer、输入哈希、单位和验证结果；关键结论通过稳定 id 关联证据。每类证据各自验证数据结构，不试图把所有科学输出塞进一个数组格式。

**验收：** 特意损坏的证据被明确拒绝；合法的“不适用”带理由且可被复核；版本 1 能继续查看旧报告，但不能冒充版本 2 的完整验收。

### 任务 4：补齐研究成果到正文的转化

**修改：** `templates/paper_skeleton.py`、论文生成模板及写作指南。

- [ ] 写作前生成逐问内容矩阵：难点、假设与推导、算法输入输出/步骤/停止条件/计算规模、结果表、验证证据、解释和局限。
- [ ] 核心结论连接到证据及实际章节/图表编号。主文、附录、支撑材料分配均要有位置；关键结论不能仅给文件路径。
- [ ] 为机理、优化、数据分析分别给出原创的小型展开范例；指导共享模型、简单小问和复杂小问的篇幅分配，不要求小节等长。
- [ ] 摘要逐问包含方法和真实核心结果；正文数值和表格读取统一结果源；增加符号、单位、舍入与引用一致性检查。
- [ ] 当体量不足时，按“未展示的关键证据、缺失推导、算法细节、结果解释、稳健性实验”补实质内容；必要时返回实验阶段。

**验收：** 空标题、占位文本、算法节只写模型定义、正文引用不存在的图表、数字与结果源不一致都不能通过交付检查。语义缺陷保留章节定位供评审，不声称正则可全自动识别。

## 测试与里程碑

1. **M1：验收尺子可信。** 完成任务 1–2，确认同口径测量、阈值冻结、干净发行和隔离环境可用。
2. **M2：现有薄弱论文不能被误报完成。** 完成任务 3–5；旧 B 题在新交付验收下必须返回缺陷或需复核，旧结构审计仍可保持通过。用合法小型案例确认不是一律拒绝。
3. **M3：完整未见题验收。** 完成任务 6，一题通过并公开逐项结果；扩展验证另计，不以单题成功宣布所有题型成熟。

每个任务先写针对真实失败方式的回归测试，再实现，再跑对应测试。最后运行现有 162 个测试和新增套件，并在源仓库不可访问的环境中完成整条求解到 PDF 的集成测试。测试套件通过、软件版本完成、整题验收通过是三个分别报告的状态。

**实施优先级：** 测量与隔离 → 证据及正文转化 → 图像/PDF 检查 → 留出整题验收。未证明前一阶段有效时，不靠继续增加算法目录代替验证。
