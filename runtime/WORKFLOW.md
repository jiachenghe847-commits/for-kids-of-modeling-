# Blind Runtime Workflow

Use only the supplied official input and the frozen toolkit. Initialize a case, record repeated runs, generate the paper from `artifacts/results.json`, then run the structural, evidence, figure, PDF, compliance, and independent-review audits. Do not use corpus, drills, or same-problem material during a blind run.

Before solving, freeze any competing interpretations as named scenarios in `case.json`. For optimization with explicit priority words, use staged lexicographic objectives and retain every solver status. A time-limited incumbent is a feasible result, not a proof of optimality. Re-read exported tables with `parse_number` and `compare_tabular_records` so signs, decimals, identifiers, and schedule fields are checked independently of the solver's in-memory arrays.
