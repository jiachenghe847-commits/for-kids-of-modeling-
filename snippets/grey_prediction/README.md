# 灰色系统（GM(1,1) 预测 / 灰色关联分析）

本目录含两个用途不同的方法：`gm11_forecast` 做**预测**，`grey_relation` 做**评价**，别混用。

## 一、GM(1,1) 灰色预测（`gm11_forecast`）

**什么时候用**：样本量少（一般 4-10 个数据点）、呈近似指数增长/衰减趋势的时间序列，数据点太少不适合用 ARIMA。

**参数怎么调**：没有超参数需要调，输入就是原始序列；`steps` 是往后预测几期。

**结果怎么解读**：`a` 是发展系数，`abs(a) > 2` 时模型不适用（级比超出可行域），要在正文里做级比检验，不能直接跳过。

**常见坑**：
- 数据点少于 4 个或波动很大（不是近似指数趋势）时强行用 GM(1,1)，预测会很离谱
- 不做级比检验就直接报预测结果——这是灵敏度分析/模型检验部分该做的事，见 `analysis/judge-deductions.md`

## 二、灰色关联分析（`grey_relation`，评价用）

**什么时候用**：样本量小、指标间关系不明朗时的评价/排序方法，衡量各被评价对象与"理想/参考序列"的接近程度。是熵权法/TOPSIS 之外的又一种评价手段，尤其适合小样本。

**参数怎么调**：`reference` 参考序列常取各指标的最优值（如每列最大值）构成的理想对象；`rho` 分辨系数一般取 0.5。评价前指标要**同向化**（成本型指标先转成效益型），代码内部做均值化无量纲。

**结果怎么解读**：`grade` 是各对象的关联度（0~1，越大越接近参考序列），`rank` 是排名。关联度差距很小时要谨慎下"谁明显更好"的结论。

**常见坑**：
- 成本型指标没同向化就直接算，方向反了
- 参考序列怎么定的不交代——评委无法判断评价基准
- 把关联度当成绝对得分，它本质是相对排序
