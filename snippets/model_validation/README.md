# 模型检验（精度 / 稳定性 / 约束 / 交叉验证 / 灵敏度 / 联合拟合 / 系统误差）

**什么时候用**：建完模型、报结果**之前**的必经环节。评委扣分点里"只报结果不做检验"是高频项——预测/拟合类要给精度指标和残差分析，机器学习类要给交叉验证，几乎所有模型都该做灵敏度/稳健性分析。配合 `snippets/plotting/`（残差图、灵敏度曲线、收敛曲线）出图。

**参数怎么调**：
- `residual_stats` 直接传真实值和预测值即可，无参数。
- `cross_validate_score` 的 `k` 默认 5 折；样本少用 `k=len(y)`（留一法）；分类问题可传 `scoring="accuracy"`，回归传 `scoring="r2"` 或 `"neg_mean_squared_error"`。
- `sensitivity_analysis` 的 `func` 要包成"参数字典 → 单个关键指标"，`deltas` 是扰动幅度，默认 ±5%/±10%。
- `multi_seed_summary` 接收 `run(seed)` 和种子列表，保留每次原始记录并汇总最好、最差、均值和标准差；随机优化正文至少报告 3 个种子。
- `compare_objectives` 比较主算法和独立参考算法，`degradation > 0` 表示候选方案更差，最大化和最小化使用同一符号约定。
- `constraint_residual_report` 接收逐条标量约束（`lhs/relation/rhs/tolerance`），返回每条残差、违反量、总体可行性和最大违反量。
- `joint_fit` 用于**几组数据共享一部分参数**的场景（不同角度/温度/批次测同一个对象）。传 `forward(shared, local, dataset)`、共享参数名、各组独立参数名和初值，它同时给出联合解与「各组单独拟合」的对照。
- `subrange_drift_scan` 把待求量在数据的不同子区间上各算一遍，传 `estimator(x_sub, y_sub) -> 标量` 和区间列表即可。

**为什么要联合拟合而不是各算各的再平均**：若干量在各组之间本来就该相同，分开拟合等于扔掉了这条硬约束——各组会各自漂到不同的值，组间散布反而成了主要误差来源。2025 B 题演练就吃了这个亏：两个入射角各拟各的，厚度分别 7.4517 / 7.5925 µm，角度间半散布 0.0704 µm 直接成了主导不确定度；同题官方优秀论文 B157 用双角联合拟合共享厚度与色散参数，从源头避开了这个问题。返回值里的 `comparison` 给的就是「不联合的话本该相同的参数会散布多少」，**这一项才是要写进论文的**。

**子区间漂移扫描建议当标准动作跑**：模型里没建进去的系统效应（色散、老化、季节性、量程非线性）通常不会让残差变难看，而是让**估计值随所用数据区间平移**。只在全量数据上算一次完全看不见，分区间各算一次立刻暴露。`monotonic=True` 的漂移几乎一定是漏建模，来回跳则更像噪声。2025 B 题里这个扫描测出光程随波段漂移 12%（硅）与 34%（碳化硅），直接解释了三篇同题论文结果分歧的来源。

**结果怎么解读**：
- `r2` 接近 1、`rmse`/`mae`/`mape` 越小越好；`residuals` 画出来应无明显趋势/异方差（有趋势说明模型没吃透数据）。
- 交叉验证 `mean` 是泛化能力估计，`std` 大说明模型不稳定/对数据划分敏感。
- 灵敏度 `elasticity`（弹性系数）绝对值越大，说明结果对该参数越敏感——这些参数要重点讨论取值可靠性。
- 随机优化不能只引用最好的一次；均值和标准差用于说明稳定性，完整 `runs` 应写入实验 JSON。
- 约束报告的 `feasible=True` 才能把方案写入正式结果表；存在违反时应先修复参数化或罚函数，而不是四舍五入掩盖。

**常见坑**：
- 只用训练集精度当模型效果——务必上交叉验证或留出测试集
- `mape` 在真实值含 0 时失效（代码已跳过 0 值，但正文要说明）
- 灵敏度分析只做一两个参数、或只在正文说"结果稳健"却不给数据——要有扰动表/曲线支撑
- 用同一个目标函数和同一段代码冒充“独立验证”——交叉验证应换算法、换实现、用解析特例或缩小规模精确解
- 分层/贪心算法没有与联合优化做缩小规模对照——不能据此声称分解没有损失
