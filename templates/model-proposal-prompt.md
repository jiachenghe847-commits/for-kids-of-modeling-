# 建模方案生成提示词模板

对应设计文档组件⑥。赛时拿到题目/子问题后，把下面的模板填好赛题信息，直接发给 Codex/Claude。

## 提示词模板

```
你是数学建模竞赛的建模顾问。这是本届国赛的一道子问题：

【题目原文】
<粘贴子问题原文>

【已知数据/约束】
<粘贴题目给的数据说明，或列出目前拿到的数据情况>

请完成：
1. 提出 2-4 个候选建模方案。每个方案说明：
   - 用什么方法（具体到方法名，比如"层次分析法"而不是"数学方法"）
   - 为什么适用这道题（结合题目的具体条件，不要套话）
   - 需要什么数据/前提，我们现在是否已经具备
   - 预期能得出什么形式的结果
   - 主要局限是什么
2. 在提出方案前先做“目标口径审计”：
   - 写出待求量、单位和统计口径
   - 列出题目中可能造成不同数学目标的歧义
   - 对每个合理口径分别给出数学定义，不要擅自替团队选择
   - 把“优先保护/尽量保持/可重新安排/最多或最少”等表述拆成命名情景，列出固定对象、可调整对象和边界
3. 对每个候选方案给出正式模型卡草案：
   - 决策变量、状态量和已知参数
   - 目标函数或评价指标
   - 等式/不等式约束
   - 题设假设与新增假设
   - 核心方程需要映射到哪些代码函数和单元测试
4. 给出计算与验证方案：
   - 一个透明的基线方法
   - 主求解方法及其停止条件
   - 若使用贪心/分层/分解，如何在缩小规模上与联合优化比较
   - 需要保存的收敛、多随机种子、约束残差和独立验证产物
   - 若是分层目标，说明每一层如何锁定上一层最优值；若有限时，说明如何记录 incumbent、上下界、停止原因和最优性间隙
   - 说明如何从导出的 Excel/CSV/官方表重新读取并逐字段核验负号、小数、编号和单位
5. 如果 cumcm-toolkit/snippets/ 下有匹配的脚手架，指出具体是哪一个。
6. 不要在这一步直接写正文或编造数值结果——只提方案和实验设计，我们确认目标口径与方法后再进入实现。
```

## 使用说明

- 拿到 AI 给出的多方案后，团队讨论选定方向，**不要**让 AI 替团队做最终选择——AI 提供选项和权衡，拍板是人的事
- 盲测阶段只提供官方题目和附件，不要把 `corpus/`、`建模/` 中的同题论文交给 AI；赛后复盘另行进行
- 选定方向后先运行 `templates/init_contest_case.py`，填写 `case.json`，完成模型、代码和验证后再起草正文
- 正文所有数字必须来自 `artifacts/results.json`，由生成脚本插入；不能手工转抄
- 起草前后分别运行 `checklist/case_audit.py <比赛目录>`，起草完成后再走 `checklist/manual_verification.md`
